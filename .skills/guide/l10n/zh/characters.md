# 角色、人设与群组

你游玩的一切都存在于四个板块中：角色、群组、人设和市场。本页说明各自的用途；帮助文章*你的角色*、*卡片编辑器标签页*和*角色群组*有详细说明。

## 卡片

卡片就是一个角色：描述、性格、场景和第一条消息。写入 `group: Guild of Ravens` 或 `faction: Guild of Ravens` 的标签也会把卡片中的角色加入该群组，因此告诉群组的记忆事实他们也会知道（[[litopys]]）。角色板块以网格或列表显示你的卡片，带有搜索、标签、文件夹、收藏（星标）和多种排序。打开卡片即可编辑。编辑会保留在草稿中，直到点击 "Save changes"；带着未保存的编辑离开时会先询问。

编辑器有六个标签页：

- **Core**：卡片文本、对话和问候语。
- **Profile**：将同一段描述拆分为结构化字段（身份、外貌、目标）。每次保存都会把它们写回卡片文本。旁白卡片可以在这里描述整个角色阵容。
- **Soul**：角色如何回应你，以及习惯。见 [[soul]]。
- **Memory**：角色记得的已结束聊天。见 [[memory]]。
- **Lorebook**：链接到此卡片的书。
- **More**：颜色和声音、精灵图（见 [[sprites]]）、画廊、正则、高级设置。

一张卡片可以同时扮演多个角色（旁白或游戏主持人）。在 Colors 下，"Voices" 为每个说话者赋予自己的颜色。如果你没有列出任何声音，聊天会替你完成：一张包含多个角色的卡片（每个角色对应一个命名的段落）会自动为每个角色的台词着色，各用不同颜色，并随聊天保存。在其他任何聊天中，打开聊天菜单 "Voice colors" 并打开开关；"Spread colors" 会为你尚未挑选的每个人分配不同颜色。这需要 Relationship 仪表盘，它提供角色列表。 当声音被上色时，台词会取说话者的颜色：开头的名字（"Rhea:"）、说话动词旁边的名字（"— 不，— Esh 说"），或指向同一回复中先前提到的、该性别唯一角色的她或他（"— 好吧，— 她说"）。不在列表中的说话者（仅在故事中出现的路人）会获得自己的颜色，每次都相同，并与已用颜色保持距离。不提及任何人的台词保留上一位说话者的颜色；在有人被提及之前，保持主题的颜色。如果故事用与卡片不同的名字称呼角色（卡片是"Aphrodite"，故事里说"Ada"），聊天可能会列出两个人并分别着色。将二者合并的两种方法：在 Relationship 仪表盘中打开角色菜单并选择"Same person as..."，或在卡片中添加一行"Also called: Ada"，使该名字从第一条回复起就被识别。句中引号里的短词（"称之为«背叛»然后离开"）被视为术语而非说话，不会着色。要查看某句台词为何获得该颜色，打开聊天菜单，"Voice colors"，并打开"Show who speaks and why"：每个引号后的小标记会注明说话者和规则。

## 人设

人设就是你：名字、代词、描述、头像。只要提示词中提到用户，模型就会看到它。"Use this persona" 使其成为你的默认人设，并将当前打开的聊天切换为它。人设可以携带自己的 lorebook，也可以锁定到选定的角色，这样与他们开始的新聊天会以它开场。人设的 Lorebooks 标签页列出它携带的书（打开一本、取消链接、从可搜索的列表中添加更多，或新建一本）。人设可以拥有自己的书（在空标签页上点击 "New book" 创建，"Replace" 替换它）：它随人设文件一起保存，因此 Export 和 Backup 会携带它，在另一台设备上导入该文件时会将其恢复并保持链接。仅链接的书留在该设备的库中；书缺失的链接会显示为 "Not in your library" 行，你可以将其移除。Personas 屏幕上的 Import 可以从其他应用导入一个人设（一个名字和一段描述）、多个人设的备份，或一个 `{ name: description }` 列表；引用了你尚未导入的书的人设仍会被导入，并注明缺少哪些书。

## 群组

一个群组可将多个角色置于同一聊天中。"New group"打开一个选择器（搜索、收藏、标签、发言顺序）；"Next"创建群组并打开其编辑器，在此处"Start chat"开始首次聊天。编辑器包含Overview、Members、Scene、Turns、Direction、Lore和Chats选项卡。Direction选项卡和群组聊天中的输入栏在[[direction]]中有详细说明。Turns选项卡决定谁将回复：Narrator（一次回复代表所有人发言）或Each in turn。新群组默认以Narrator模式开始。

Turns 标签页还有 **How they talk**：**Interruptions**（成员会插话、互相抢话，或在符合其性格时忽略问题）、**Own goals**（当计划违背他们的本性时，成员会反对、讨价还价或拒绝，即使这会与你产生紧张关系）和 **Draw in quiet members**（沉默了一段时间的人会获得更多回答机会，旁白场景也会被要求把他们带入）。前两项为 Off、Can 或 Should：Can 在符合场景时允许，Should 则期望如此，如果每条回复都变成争吵，就回到 Can。新群组以 Can 和 Draw in 开启；旧群组在你开启之前保持全部关闭。聊天自身的 Turns 按钮可以仅为一个聊天更改它们。在 Members 标签页中，打开成员的 "In this group" 部分，给他们一个仅此群组使用的 **voice**：最多两种说话习惯（说话断断续续、从不提问）和最多五句示例台词。几句话比形容词更能教会节奏，不同角色对同一消息应有不同回应。

群组不是卡片：删除群组会删除其聊天，但绝不会删除其成员。没有自己颜色的成员会自动获得不同颜色。

## 获取卡片

- "Import card" 接受 PNG 或 JSON 文件，一个或多个，以及指向 Chub、RisuRealm、CharaVault、Botbooru 或直接文件的链接。
- 市场会同时搜索多个来源；打开结果可在导入前阅读完整卡片。每个来源有自己的排序和成人内容过滤器，有些需要手动下载。
- Export 写出一个内含卡片的 PNG。
- Home 上（以及 Lorebooks 中）的 "With Molfar" 会请 Molfar 与你一起起草卡片或 lorebook。见 [[vertep:molfar]]。

## 来自卡片的信

一张你很久没玩的卡片可以用自己的口吻给你写一封短信。信会以绿色 Letter 的形式到达收件箱（Home 的 "Waiting on you"、侧栏中的收件箱按钮）；打开它会带你到旧聊天，或为你从未玩过的卡片开始一个聊天。信绝不会写入聊天，也绝不会虚构事件。

它**在你开启之前是关闭的**。关闭期间，一张绿色卡片 "Let your characters write to you" 会显示在角色板块顶部和 Home 的 "Waiting on you" 中：**Turn on** 立即开启，**Not now** 永久隐藏该卡片。各项数值（闲置天数、每天信件数、同一卡片两封信之间的天数、写作模型）和你停止的卡片在 Characters、More、Letters from cards 中。应用打开时每隔几小时检查一次信件：闲置 14 天的聊天、14 天未玩的卡片，以及没有 Soul 的已玩卡片（一次）。如果写作模型连续三次检查失败（或未设置），收件箱会显示红色的 "Letters" 失败及原因，Open 会带你到 Letters 设置；收到一封信、更换模型或关闭信件都会清除它。

## 为没有头像的卡片绘制肖像

没有自己图片的卡片（什么都没有，或默认头像）可以被绘制。**单张卡片：**在卡片编辑器中，肖像下方的 "Draw" 会打开一个对话框：选择图像模型，文本模型（Card tasks 模型）会写出卡片描述，你可以编辑，然后图像模型将其绘制出来。图片会立即进入卡片的 Gallery，"Use as portrait" 使其成为头像。**多张卡片：**Characters、More、"Draw missing portraits (N)" 会询问使用哪个模型，然后通过进度卡片依次绘制；Cancel 会在卡片之间停止，失败的卡片会连同原因列出。

"Draw with" 列出 Settings > Images 中的图像模型：本地 ComfyUI 或 Forge，以及 API 模型。首选是应用自带的图像模型（Extensions > Image generation）；此处选择仅对肖像记忆。标签训练的模型会得到一行标签，API 模型会得到一段文字。只有名字的卡片没有可描述的内容，对话框会说明这一点。图像生成必须开启（Extensions）；对话框会提示并为你打开。

## 卡片不保存的内容

Dashboard 状态、章节和事实属于每个聊天，而不是卡片。卡片的 Memory 标签页（保留的习惯、“How they changed”）也不属于卡片，永远不会出现在导出中。相比之下，Soul 保存在卡片中。
