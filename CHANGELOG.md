# Changelog (Molfar Vertep fork)

Changes on top of upstream Roleplay 4.18.2 (`b509845`).

## Unreleased

- Agents can read the Dashboard (#132). An Input entry or an If rule with `source: "state"` reads one of 13 fields: the scene's `present`, `place` and `weather`, and per character `mood`, `condition`, `outfit`, `holding`, `goal` and the five disposition numbers (`trust`, `comfort`, `attraction`, `respect`, `affection`). `of` names the character; without it the field is about whoever spoke last. The host takes the newest Dashboard snapshot on the chat's own line (a swiped-away branch is not seen), and the install screen asks for the field alone. Anything else of the Dashboard stays closed (`E_DASH_FIELD`); writing is still not supported. Tests in `rp-agents-plugin.test.ts`, docs in `docs/DATA-FORMATS.md`, the `agent-craft` skill updated.

## 4.79.1 (2026-11-01)

- The World book fills itself from the story, whatever the DM's level (#185). Report: a chat 12 turns into a school story had 0 records, because the DM model decided a changing room and a school corridor were not worth a record. Now code reads the places the scene tracker named along the chat and the things it saw lying around (including what was left behind when the story moved on), takes away what the book already has, and a small records-only run offers the rest to the DM model by name ("Named in the story by the scene tracker, with no record yet"). It runs after a reply, only when there is something new to offer, once per name (what the model declines is not asked again), and also with the DM set to Off: Off now means no events and no dice, while the book keeps filling and "World · here" keeps going into the reply prompt. A chat that never had a world (an assistant card) is left alone.
- The Dashboard keeps what characters wear and hold, and where everyone stands (#185). Reports from Discord: the sensor dropped outfit details ("pink soft knit cardigan" became "a cardigan"), colours drifted, and a reply that did not mention clothes lost them from the prompt. Now the sensor reports changes only (outfit and holding as add/remove lists, `at` for a character, `userAt` for you, `objects` for what lies around) and the plugin keeps the lists: an item is matched by its words, so a removal of something that is not listed changes nothing, and a worn thing that is put down moves to the scene objects with where it lies. Positions and objects start over when the story moves to another place. A known outfit stays in the reply prompt on turns that do not mention it. A character with no clothes on record is asked to be described in the next reply (the sensor then picks the description up, no extra model call). The Previous state the sensor reads now lists Wearing, At and Objects. The part is in the Dashboard block of the prompt inspector and has its own switch in Dashboard settings ("Remind the model where everyone stands and what they wear", on by default, about 40 to 100 tokens). A plain text outfit from an older custom sensor prompt still works as a full report, with the earlier wording of an item kept when the new text only says less of it. The sensor prompt changed, so the previous default counts as the default.

## 4.73.1 (2026-10-28)

- A big imported library no longer stops the app from starting. The start-up list (`GET /bootstrap`) sent every lorebook whole, and a SillyTavern import brings a book per character (about 100 KB each), so past roughly 1,000 characters the plugin ran out of memory: "Can't reach the engine ... out of memory", and an import running at the same time died with "worker exited". Books now come as summaries (name, folder, switches, linked cards, number of entries and a token estimate; no entries), from an index in the app's local cache like the characters, and a whole book is loaded when it is opened. A card export loads its own book first, so nothing leaves without it. `GET /lorebooks?summaries=1` is the new list route; `PUT`/`PATCH` of a summary (`stub: true`) answers 409. Sending a message also read and parsed every book file of the library before keeping the ones in scope; it now reads only the books in scope (`readBoundBooks`), and so does Litopys' repeated-source check. No change to the files on disk.

## 4.73.0 (2026-10-27)

- Chat header, Agents: the quick-switch bar at the top of a chat gets an Agents segment (how many are on, once the list is read) beside preset, persona and model, so it is in view at once. Each segment now opens the palette on its own tab.
- World DM, dice (off by default): a DM profile option. Before a reply is written, code rolls 2d6 plus one of the speaking character's Dashboard numbers (trust, comfort, attraction, respect or affection, a twentieth of it, so -5 to +5; by default "By the action": code rolls one die and hands the model the result for each present character's stats, and the model takes the person the action is aimed at and the stat it leans on; someone without Dashboard numbers gets the bare dice) and tells the model how an uncertain action turns out: miss, no but, yes but, or full success. Three positions: Off, Hint, Binding, one explanation shown at a time. Hint (the model may soften the result to stay in character) and Binding (it may not). No extra model call; a share of replies gets a roll (25% by default). The line shows in the prompt Inspector as "Dice", and every roll, quiet ones too, is kept per chat (`GET /world/dice?chatId=`, last 30). It follows the DM's guards: explicit scenes, combat (except Antagonist and Chaos), the prompt board switch, and a level above Chronicler with Insert on. A swipe rolls again, a reload does not. The switch sits in the chat's World DM sheet, under Send events to the story, and holds for that chat only; the profile's Options card holds the default for every chat on it. A third switch, How luck runs (Kind, Even, Harsh), moves the limits between the four outcomes by one. The sheet also folds away a list of the last ten rolls. The note also covers a player who already wrote how the action ends: the outcome stays and the roll sets how the others react and what it costs. A fourth setting, World intervenes (percent, off by default), is its own roll apart from the action's: when it hits, a d6 sets how big the intrusion is (small, real, large) and a "Life" line joins the prompt; a waiting DM event replaces it for that reply. A switch in the Dice card, Show under the reply, puts a small mark under each reply that had a roll (the dice, or the world intervening); it covers the last 30 or so replies. GitHub #155, part 1.

## 4.72.0 (2026-10-27)

- Litopys memory no longer hides a chat that fits the window: the cut (the oldest messages a chapter replaces) is now a ceiling, and only as many covered messages leave the prompt as the model's window has no room for. A chat that fits keeps every message word for word, as SillyTavern does, and the chapters ride along as a summary. Before, everything a chapter covered left the prompt except the last 20 messages, whatever the window, so a 150000 window with 100000 tokens of history still saw 20 messages and summaries of its own replies. "Recent messages kept" is now the least that stays word for word, and its default is 100 (was 20). A chat that already stored 20 keeps it, but the window decides now, so it matters little. The engine writes where the prompt's history started (`litopys/prompt-cut/<chat>.json`) so the Litopys insert carries a chapter for every message the window dropped. A long chat on a big window now sends much more each turn, and so costs more on a paid model; set the window lower in the model's settings to cap it. The chat's "older in the record" and "out of context" lines follow the last real prompt. The Prompt board, the prompt peek, the lorebook status and the keyword test now budget with the chat's model window like a send (they used the 32768 fallback, so they showed a prompt a long chat never got). Who counts as present without a Dashboard snapshot is still decided from the last 20 messages.
- Litopys, a second way to cut, "By scenes" (Settings, Litopys, In the prompt, "Older messages leave the prompt"): as soon as a chapter holds a scene, the whole scene is replaced by it, and only the direct messages after it stay. A scene of 12 turns is sent in full until the chapter exists and two more turns are in; from then the model gets the scene's summary and the 2 direct turns, and so on scene after scene. A scene goes whole or not at all, never in part. "Direct messages after the scenes" is 2 or more with no upper limit (a very large number cuts nothing). The window still trims the rest if it has to. The default stays "Only when the window is full". For slow-burn stories with a lot of prose that matters less than what happened before and the pinned facts. Settings keys `cutMode` and `sceneKeep`; see docs/DATA-FORMATS.md.
- Coloured dialogue in your own message: when you write other characters' lines in your reply, a line that opens with their name and a colon (`Keiko: "..."`, `**Masa:** "..."`) now takes that character's dialogue colour instead of your persona's, as the model's own replies do. It works for a group's members, for the voices of a Narrator card, and for the chat's own character when it has a dialogue colour. Only the label counts, never a name said in the narration: `Aria watches him. "I am tired," I say.` stays yours. The colour holds on the lines after a label until another label, and your own name (or any label that is not a character) hands it back to your colour. A character's line written without a label stays in your colour.
- The context window is the model's alone: a preset no longer carries a window. The field is gone from the preset editor (Samplers shows the model's window read-only), from imports (ST `openai_max_context`, Studio `max_context`) and from the built-in presets, and a window stored in an old preset file is ignored. The window comes from the model: the catalog, the provider's model list, or the number you set in the model's own settings. When none is known the app assumes 32768 and says so under the chat, with a "Set it" button and a close X (remembered per model). Before, a preset's own number (16384 when absent) could silently cut a long chat's history on a model with a much larger window. See docs/DATA-FORMATS.md.
- Agents, how often an agent runs: in the Agents sheet, an installed agent's "Model, limits and pace" has "Runs every N replies" (1 to 50). It overrides the author's cadence for you only, lives in your `agents/config.json` (`byAgent.<id>.everyN`), and "Use the author's" clears it. It is per installed agent, not per chat.
- Agents, a bigger Input: the Input card's history source has "Most recent messages" (`last`, 10 by default, up to 60) in the form, and "Most tokens" (`tokens`, 100 to 100000): the oldest rows are dropped until the text fits, the newest message always stays. The count is an estimate (script-aware, so Ukrainian text is not undercounted). It is a cap the author sets, not an automatic fit to the role model's window: a plugin does not know that window.
- Agents, Try shows the size: each asked model's card in Try says `~N tokens in`, so you see what the agent sends before it runs on a small model.
- Fonts for replies (#126): a reply, or your Custom CSS, can name `Caveat`, `Marck Script`, `Lobster`, `Playfair Display`, `Cormorant Garamond`, `Oswald`, `PT Mono` or `Ruslan Display` in `font-family`, and the app now has them (Latin and Cyrillic, bundled with the app, nothing fetched from the net; a browser loads a file only when a page uses the family). A reply still cannot bring a font: `@font-face` stays stripped. The fenced html block runs in a sealed frame that does not see the app's fonts, so they apply to the reply's own text, not inside that block. A self-sizing html block stays open in #126.

## 4.71.0 (2026-10-26)

- Agents, a block for results: in a chat's Agents tab, the place button of an agent has a new switch, "Also show in the block". An agent with it on keeps its latest result (notes, hints for the next reply, choices, changes to its state) in a folded block above the message box, next to the place it already shows in; the block stays when the history scrolls away. It is per chat, saved in the chat's agents binding (`also`), never goes to the model, and the places themselves are unchanged.
- Vertep Lite: a new pick, Fiction frame (Off by default, in Choices). For models that refuse, soften or lecture on dark themes: when it is On, a short block in the fixed start says the story is fiction for adults and dark material (slavery, war, cruelty, coercion, desire) is written the way the world has it, without disclaimers or leaving the story, and a one-line reminder follows the newest message. Everyone in a sexual scene is an adult in the story; a child never takes part. Costs about 250 tokens while On, nothing while Off. It is not tied to a model.
- Built-in presets reach you on update: when you update the app, a built-in preset copy that is still read-only (FRANKENX, Molfar, Vertep Lite) takes the text the app ships, so a change to the shipped preset, like the HTML panels pick in Vertep Lite, no longer stays behind in a workspace that already had the preset. A copy you made editable keeps its text. A hint typed by hand into a read-only copy is replaced too.

## 4.25.0

Memory v2: one story memory per chat, Litopys, which you can see and edit in the Library.

- **Litopys is the chat's memory.** It cuts the story into scenes and, in the background, writes one chapter per finished scene (what changed, not a retelling) and the facts that came out of it: who they are about, who knows them, their kind (event, trait, lasting change, relation, world, plan) and weight. A scene gets its chapter once the next scene begins. The memory model is set in Litopys's settings (empty = the chat's own model).
- **Long chats stay in the model's window.** Messages Litopys already holds leave the prompt, except the newest ones (Recent messages, 20 by default), which always go word for word; in their place each reply carries one Litopys block within a token budget (800 by default): pinned facts first, then traits and lasting changes of the characters present, the last chapter that left the prompt, then other facts and chapters by relevance. A character only gets facts they know. Messages that left the prompt are dimmed in the chat, with a divider.
- **Arcs**: when the older chapters outgrow a threshold (twice the budget by default), neighbouring chapters can merge into one short arc that rides the prompt in their place; the chapters stay in the record. By default the Library asks first (Merge, Not now, Always merge automatically). Every number is a setting.
- **The Library** (the rail section that was Litopys) shows every chat's record two ways. **Overview**: the chapters as a timeline with their facts, arcs as bands over their chapters, the waiting proposals, and a card per character (pinned facts, traits, changes, relations, what they know about others) with a portrait you can set for names without a card. **Ledger**: tabs for chapters, facts, proposals and activity, with filters and search. In both you edit, pin (up to 5 per character), retire, restore and delete facts, edit, rewrite or delete chapters (and keep a scene out of the record), and accept or reject what Litopys proposes. A line says what the worker is doing (writing, waiting, failed and retrying, stalled). A map shows chats and the chats forked from them.
- **Back to the source**: "Open the messages" on a chapter or a fact shows the messages it came from, and the Ledger searches the original messages, never the summaries.
- **The chat's Memory item** opens its record: how many messages left the prompt, what the last reply carried, and **Rebuild from scratch**, which writes a new record beside the old one and swaps it in when done (your own, edited and pinned facts and your edited chapters stay).
- **The built-in Memory is gone**: its summary and facts move into Litopys by themselves (the old memory file is removed after the move), as do Litopys 1.x facts. Roleplay Settings has a Litopys section instead: model, recent messages, insert and budget, scene sizes, pin limit, arcs and the prompts.
- **Records are written in English** by Litopys, the dashboard's sensor and fast mode, whatever the story's language, so they hold up across models; names stay as the story spells them.
- **The history fits the context window by tokens**, keeping room for the reply and for the dashboard's and Litopys's inserts; Next, swipe, Continue and Impersonate use the same matching as Send.
- **Dashboard**: notes follow the scene, near-duplicates are not written, the sensor gets the newest and the most relevant notes, and important or key notes older than 30 turns move into Litopys facts.
- A chapter that comes out longer than its messages is asked for again, shorter. Replies some models return in a flat shape are read. Deleting a chat deletes its memory too. A language stored before 4.20 ("English") is read again instead of the browser's.
